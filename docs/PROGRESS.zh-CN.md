## 里程碑 1：骨架与最小闭环 —— 已验收（2026-10-31）

已交付：

- SQLite 存储和带版本号的迁移；文档保存原始下载和清洗后的正文；题目、标签、切块、FTS5 索引和向量全部持久化；
  向量快照带启动时一致性检查（只补新增部分；丢失时从数据库重建；从不重新计算向量）。
- 可配置的 agent：后端（OpenAI 兼容接口、CLI agent）和带备用链的角色，分层配置和环境变量覆盖，能力校验，
  `sde-rag agents show`、`sde-rag doctor`。
- 模型调用的卡死侦测：流式输出的首个 token 超时和间隔超时，结构化调用的硬性超时，输出重复循环检测，卡死后的健康探测和熔断。
- 身份与权限接口（默认：单用户、全部可见），检索链路全程经过它，并用限制性的策略做了测试。
- 连接器：GitHub 题库仓库（41 个）、Hacker News（Algolia API）、dev.to（公开 API），支持增量列表、“已见过”记录、
  条件请求、内容哈希和跨来源链接识别。
- Markdown 规则问答抽取（标题题目、编号列表里的标题、`<details>` 折叠块、题目列表），基于可配置分类体系的规则打标签和 LLM 打标签，
  完全相同的题目合并，并计算出现次数和热度。
- 混合检索（BM25 + 向量，RRF 融合）；查询图支持列出某方向的常见题和带引用的回答，校验引用，模型失败时给出降级回答。
- 抓取图：运行标识、数据库锁（持有者进程不存在时可接管）、心跳、断点续跑。
- 最小的评测图（检索自检）、带 `/health` 的 Gradio 网页界面、命令行。
- 公开数据集导出（`sde-rag publish-data`，Git LFS），不含本机使用数据。
- 测试：不需要网络的单元测试；在 `langgraph dev` 里运行查询图的集成测试。

第一次真实抓取（2026-10-31）：486 篇文档（GitHub 文件 314 个、dev.to 文章 150 篇、Hacker News 讨论 23 个），
6,535 道不同的题，7,585 个切块，用 `intfloat/multilingual-e5-large` 计算向量。

验收（2026-10-31），对照 DESIGN.zh-CN.md 第 12 节的标准：

| 标准 | 结果 |
|---|---|
| 在界面里问“Python 常见面试题”，返回带引用的题目列表 | 通过：27 道题，全部来自 Python 题库，每条都有引用，没有无效引用（本地模型，约 22 秒） |
| 问一道具体的题，返回带引用的回答 | 通过：“如何设计一个限流器（rate limiter）？”（网关模型，35 秒），以及在网页界面里问 “What is the difference between a process and a thread?”（21 秒） |
| 重启后不重新计算向量 | 通过：界面和命令行都从向量快照加载；对全部 521 篇文档重新建索引时，1,395 个文档切块全部保留，没有计算任何向量 |
| 连续运行两次，第二次没有重复下载 | 通过：两次强制运行（列出全部来源，忽略间隔）：重复下载 0 次；GitHub 仓库在提交没变时返回 304；第二次运行下载 0 篇文档、计算 0 个向量，耗时 27 秒 |

验收中修复的问题：

- 题目列表里编造的条目：如果一行列表只引用了上下文之外的标签，现在整行删除，而不只是去掉标签；
  命令行在校验后的回答和流式输出不一致时，会打印校验后的版本。
- 方向题目排序：请求里的泛化词（“常见”“面试题”“common”“interview questions”）不再去匹配
  “... Interview Questions”这类标题；新增“专注度”排序，优先选专门讲这个标签的来源；热度相同的题在融合时排名相同。
- 规则标签：多种语言共有的概念（“decorator”“generator”“closure”“hooks”“coroutines”）不再作为某一种语言的别名；
  分类体系版本变化时，规则标签会重新生成。
- 解析：“— Difficulty: Easy”存为难度，不再算作题目的一部分；第一人称的博客标题（“What I took away”）不算题目。
  旧版解析器处理过的文档会从已保存的正文重新解析（不重新下载），没有变化的文档切块保留原来的向量。
- 路由：如果消息本身就是一道具体的题，即使路由模型把它标成“方向”，也会直接作答。

验收后：532 篇文档（已索引 521 篇），6,633 道不同的题，8,028 个已计算向量的切块；1,200 道题由 LLM 打了标签。

已知限制（计划在后续里程碑解决）：

- 在合并近似重复之前，“常见”只能按完全相同的重复来统计：题库里“什么是生成器”有八种问法，每种只算一次，
  所以方向题目列表主要依靠来源专注度和文档内顺序。

- 只有规范化后文本完全相同的题才会合并（近似重复：里程碑 2）。
- 面经帖子以正文切块的形式入库；只有写成标题的题目会被抽出来（LLM 抽题：里程碑 2）。
- LLM 打标签每次运行处理 600 道题，其余的先保留规则标签，按顺序轮到。
- 评测图目前只检查索引能否用题目原文找回这道题（真正的评测集：里程碑 3）。
